# Multi-User Migration Plan

## Обзор изменений

Переход от single-user к multi-user архитектуре с полной изоляцией пользователей и системой онбординга.

## Ключевые изменения

### 1. Database Schema
- Обязательное поле `userId` во всех основных таблицах
- Новая таблица `UserPreferences` для настроек пользователей
- Таблица `UserBarber` для связи пользователей с барберами
- Таблица `OnboardingStep` для трекинга онбординга

### 2. Authentication & Session Management
- Telegram ID как основной идентификатор пользователя
- Автоматическое создание пользователей при первом использовании
- Сессии привязаны к Telegram chat ID

### 3. User Isolation
- Все операции с данными изолированы по `userId`
- Разговоры, встречи, барберы - все привязано к конкретному пользователю
- Отдельные уведомления для каждого пользователя

### 4. Onboarding Flow
- Автоматический запуск для новых пользователей
- Настройка языка, часового пояса, первого барбера
- Помощь с подключением WhatsApp

## План миграции

### Этап 1: Подготовка (1-2 дня)
1. **Создать новую схему БД** (`schema-multiuser.prisma`)
2. **Реализовать сервисы** 
   - `multiuser-service.ts` - изоляция пользователей
   - `onboarding/flow.ts` - процесс онбординга
3. **Обновить бота** (`multiuser-bot.ts`)

### Этап 2: Миграция данных (1 день)
1. **Создать миграцию Prisma**
   ```bash
   npx prisma migrate dev --name add_multiuser_support
   ```

2. **Скрипт миграции существующих данных**
   ```typescript
   // Создать пользователя "admin" для существующих данных
   // Привязать все существующие разговоры и встречи к этому пользователю
   ```

3. **Обновить существующие записи**
   - Добавить `userId` ко всем существующим записям
   - Нормализовать JID-ы барберов

### Этап 3: Тестирование (1-2 дня)
1. **Unit тесты** для всех новых сервисов
2. **Integration тесты** для онбординга
3. **Load тесты** для проверки изоляции пользователей

### Этап 4: Развертывание (1 день)
1. **Бэкап текущей БД**
2. **Развертывание новой версии**
3. **Миграция данных в продакшене**
4. **Мониторинг и rollback план**

## Безопасность и конфиденциальность

### Изоляция данных
- Каждый пользователь видит только свои данные
- Разговоры и встречи полностью изолированы
- Барберы могут быть общими, но связи пользователь-барбер индивидуальны

### Хранение данных
- Telegram ID хранится в зашифрованном виде
- Сообщения шифруются при хранении
- Логи содержат только анонимные идентификаторы

## Масштабируемость

### Производительность
- Индексы на `userId` во всех таблицах
- Пагинация для больших списков
- Кеширование часто используемых данных

### Ограничения
- Максимум 100 барберов на пользователя
- Максимум 1000 встреч в истории
- Автоматическая очистка старых данных

## Мониторинг и метрики

### Ключевые метрики
- Количество активных пользователей
- Конверсия онбординга
- Успешность записей к барберам
- Время ответа системы

### Алерты
- Ошибки в процессе онбординга
- Проблемы с изоляцией пользователей
- Превышение лимитов использования

## Rollback план

В случае критических проблем:
1. Остановить новую версию
2. Восстановить БД из бэкапа
3. Запустить старую версию системы
4. Уведомить пользователей о временных проблемах

## Документация для пользователей

### Новые команды
- `/start` - начать работу/онбординг
- `/barbers` - управление барберами
- `/appointments` - ваши встречи
- `/settings` - настройки аккаунта

### Изменения в существующих командах
- `/haircut` - теперь с изоляцией по пользователям
- `/qr` - персональный QR для каждого пользователя
